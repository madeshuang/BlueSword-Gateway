# 布鲁 Agent 升级提案：从“聊天选品”到“看得见思考的具身智能”

> 基于 BlueSword-Gateway（提交 `8ffb7dd`，2026-10-31）及《接口文档 v1.1》。
> 四个等级逐级叠加，每一级都可以单独上线；v1.1 的报文、路径和回复格式全程保持兼容。

## 0. 一页看懂

| 等级 | 内容 | 兰剑机器人侧工作量 | 观众看到的变化 |
|---|---|---|---|
| **一** | UI 改版 + 打开思考链 | **0** | 能看到布鲁在想什么；取物显示为“调用技能” |
| **二** | GDK 执行回报（含任务编号） | 约半天：在 5～7 个已有节点各加一行回报 | 执行中不再空白：导航、识别、抓取逐步点亮，思考链引用真实执行数据 |
| **三** | 技能化：查询库存、取货、卸货 | 约 1 天：把现有流程拆成“取”和“送”两个入口 | 布鲁会先查库存、再取货、确认夹稳后再卸货，像一个会规划的 Agent |
| **四** | 导航与视野显示（YOLO） | 约 1 天；若开放 GDK 只读接口则接近 0 | 大屏出现机器人第一视角画面、识别框和小地图，问“你看到了什么”能看图回答 |

下面用**同一个观众请求“我想吃点甜的”**，展示每一级的思考链和界面变化。

---

## 1. 思考链对比

### 现状：没有思考链

网关调用 DeepSeek 时关闭了思考（`thinking: disabled`），只要求输出 JSON。界面上的“思考”只是一个等待动画。

```
观众：我想吃点甜的

  ◌ 正在回复…                           ← 转圈，没有内容

布鲁：可以试试奥利奥饼干，甜甜的很受欢迎。
  ┌ 奥利奥饼干 × 1   [确认取物] ┐        ← 观众需要手动点确认
  
  （观众点击确认取物）

  取物任务清单  执行中
   · 机器人已接单，正在等待取物结果。
   · 取物计划：按清单定位货架并识别物品。   ← 固定模板，每一单都一样
   · 取物计划：抓取后送到交付处。

  ……接下来 1～2 分钟，界面没有任何变化……

布鲁：已取好，请到交付处领取。
```

**问题**：观众看不到 AI 的判断过程；机器人执行期间界面是静止的，看起来和普通的点单系统没有区别。

---

### 等级一：UI 改版 + 打开思考链（兰剑工作量 0）

只改我们这一侧：开启 DeepSeek 思考，流式显示；取物以“技能调用”的形式呈现。

```
观众：我想吃点甜的

  ▾ 深度思考中
  │ 观众想吃点甜的。零食区里甜的有奥利奥饼干和好丽友派；安慕希是酸奶，
  │ 偏甜但更像饮品；乐事薯片是咸的，先排除。奥利奥和好丽友派都还有库存。
  │ 奥利奥是夹心饼干，甜味更明显，盒装也更好抓取，我推荐奥利奥。
  │ 接下来调用取物技能，让机器人去货架拿一盒送到交付处。

布鲁：想吃甜的呀，奥利奥正合适，我这就去帮你拿！
  ◉ 调用技能 · 取物 · 奥利奥饼干 × 1      执行中…

  ……执行期间仍然只有“执行中”……

  ▸ 已深度思考（用时 0.8 秒）
  │ 收到机器人的完成通知，奥利奥已经放到交付处，提醒观众去领取。

布鲁：奥利奥已经送到交付处啦，记得去拿哦！
  ✓ 调用技能 · 取物 · 奥利奥饼干 × 1
```

**提升**：观众能看到“为什么选奥利奥”；界面从“选品下单”变成“Agent 决策并调用技能”。
**局限**：机器人执行期间，AI 什么也不知道，思考链在中间断档。

---

### 等级二：加入 GDK 执行回报（兰剑约半天）

机器人在已有的 GDK 调用节点之后各回报一次：导航到达、识别完成、抓取完成、返回到达、放下完成。

```
观众：我想吃点甜的

  ▸ 已深度思考（用时 1.1 秒）
  │ ……推荐奥利奥（同等级一）……

布鲁：想吃甜的呀，奥利奥正合适，我这就去帮你拿！
  ◉ 调用技能 · 取物 · 奥利奥饼干 × 1

  任务进度                                   ← 右侧面板逐步点亮
   ✓ 前往货架        停靠误差 1.2 cm          Pnc.high_precision_navi
   ✓ 识别目标        找到奥利奥饼干            Camera + 识别模型
   ◌ 抓取中…                                 end_effector_pose_control
   ○ 返回交付处
   ○ 放下物品

  ▸ 已深度思考（用时 1.3 秒）
  │ 机器人回报：已到达货架，停靠误差 1.2 厘米；识别到奥利奥并完成抓取，
  │ 已回到交付处放下。整个过程没有重试，用时 48 秒。任务确认完成，
  │ 可以告诉观众去交付处领取了。

布鲁：奥利奥已经送到交付处啦，一路很顺利，记得去拿哦！
```

**提升**：执行过程实时可见；思考链里出现了真实的执行数据（误差、用时、是否重试），而不是模板话术。
**兰剑改动**：只是“回报”，不改变任何运动逻辑，回报失败不影响任务。

---

### 等级三：技能化——查询库存、取货、卸货（兰剑约 1 天）

把取物拆成三个技能，由 AI 自己规划调用顺序：

- **查询库存**：读网关库存，兰剑零工作量；
- **取货**：机器人取到物品、确认夹稳后停下待命；
- **卸货**：带着物品回到交付处放下。

```
观众：我想吃点甜的

  ▸ 已深度思考（用时 1.2 秒）
  │ 观众想吃甜的，候选是奥利奥饼干和好丽友派。先查一下库存，
  │ 别推荐了一个已经拿完的。

  ✓ 调用技能 · 查询库存 · 零食饮料           奥利奥 3 · 好丽友派 0 · 安慕希 2

  ▸ 已深度思考（用时 1.0 秒）
  │ 好丽友派已经被拿完了，奥利奥还有 3 盒，正好符合“甜的”。去取货。

布鲁：好丽友派刚被拿完啦，奥利奥也很甜，我去帮你拿一盒！
  ✓ 调用技能 · 取货 · 奥利奥饼干             已夹稳

  ▸ 已深度思考（用时 0.9 秒）
  │ 取货成功，夹爪反馈确认奥利奥已经夹稳，现在东西在我手里。
  │ 接下来卸货，送到交付处。

  ✓ 调用技能 · 卸货 · 奥利奥饼干             已放到交付处

布鲁：奥利奥给你放在交付处啦，甜甜的慢慢吃！
```

**提升**：观众能看到 Agent 的规划能力——先查后取、确认结果再进行下一步、库存不足时会自己换方案。这是最像“智能体”的一级。
**兰剑改动**：下发接口支持 `action: "pick" | "place"`；取货完成后机器人持物待命，等卸货指令。原有的一次性取物（不带 `action`）继续可用。

### 等级四：导航与视野显示（兰剑约 1 天，或开放只读接口）

机器人回报底盘位姿和识别画面（YOLO 检测框），大屏显示第一视角和小地图。

```
观众：我想吃点甜的
  ……查询库存 → 决定拿奥利奥（同等级三）……

  ✓ 调用技能 · 取货 · 奥利奥饼干

  ┌ 布鲁的视野 ─────────────────┐   ┌ 小地图 ──────────┐
  │  [扑克牌 0.93] [签字笔 0.90] │   │  ▭ 货架            │
  │  [奥利奥 0.94]◀目标 [奥利奥 0.91]│   │    ╲               │
  │  [安慕希 0.92] [乐事薯片 0.89]│   │     ◉→  布鲁        │
  └──────────────────────────────┘   │  ○ 交付处          │
                                       └──────────────────┘
  ▸ 已深度思考（用时 1.6 秒）
  │ 我已经站在货架前。头部相机看到第二层有两盒奥利奥，置信度 0.94 和 0.91；
  │ 左边那盒更靠外，没有被签字笔挡住，更容易抓。第三层是乐事薯片和安慕希。
  │ 选左边那盒，抓取后确认夹稳再回去。

观众：你现在看到了什么？
  ▸ 已深度思考
  │ （直接看相机画面）第一层是扑克牌和签字笔，第二层是两盒奥利奥，
  │ 刚拿走了一盒……

布鲁：我眼前第一层是扑克牌和签字笔，第二层还剩一盒奥利奥，第三层是薯片和安慕希。
```

**提升**：真正的视觉理解（VLM）。思考链基于实际画面推理，观众能同时看到机器人看到的东西。DeepSeek V4.1 Flash 支持图片输入，“你看到了什么”可以直接看图回答。
**兰剑改动**（二选一）：
- 在识别阶段回报检测框和一张压缩图片，定时（约 1 秒一次）回报底盘位姿；
- 或者开放 GDK 只读权限，我们自己读取 `Camera` 和 `Slam.get_curr_pose`，兰剑几乎不用改。

## 2. 各等级的接口细节

### 等级一：无接口变化

完全沿用 v1.1。

### 等级二：任务编号 + 执行回报

**任务编号**：下发时带 `taskId`，完成和故障通知原样带回。

```json
{ "taskId": "t_20261103_0001", "items": [{ "location": "货架1-2层", "item": "aoliao", "count": 1 }] }
```
```json
{ "taskId": "t_20261103_0001", "result": "success" }
```

**执行回报**（新增可选接口）：`POST /api/task/progress`

```json
{
  "taskId": "t_20261103_0001",
  "stage": "navigate_to_shelf",
  "status": "done",
  "item": "aoliao",
  "detail": "停靠误差 1.2 cm",
  "ts": 1793546400123
}
```

| 字段 | 说明 |
|---|---|
| `stage` | 建议取值见下表；其他取值也接受，界面显示 `label` |
| `status` | `started` / `done` / `failed` |
| `item` | 可选，两件物品的任务里标明当前是哪一件 |
| `label` | 可选，中文短语，如“已到达货架” |
| `detail` | 可选，补充信息 |

| `stage` | 含义 | 对应的已有 GDK 调用（参考） |
|---|---|---|
| `navigate_to_shelf` | 前往货架 | `Pnc.normal_navi` / `high_precision_navi` + `get_task_state` |
| `detect` | 识别目标 | `Camera.get_latest_image` + 识别模型 + `TF` |
| `grasp` | 抓取 | `end_effector_pose_control` + `move_ee_pos` + `get_end_state` |
| `navigate_to_delivery` | 返回交付处 | `Pnc.normal_navi` / `high_precision_navi` |
| `place` | 放下 | `end_effector_pose_control` + `move_ee_pos` |

网关回复 `{ "code": 1, "data": "OK", "success": true }`，**机器人不需要处理回复**。

**故障通知可选补充**：`stage`（哪一步失败）、`holding`（物品是否还在手里），让 AI 能如实说明情况。

### 等级三：取货 / 卸货拆分

下发时新增可选字段 `action`：

```json
{ "taskId": "t_0002", "action": "pick", "items": [{ "location": "货架1-2层", "item": "aoliao", "count": 1 }] }
```
```json
{ "taskId": "t_0003", "action": "place", "items": [{ "location": "交付处", "item": "aoliao", "count": 1 }] }
```

| `action` | 机器人行为 | 完成通知时机 |
|---|---|---|
| 不填 | 与 v1.1 相同，取完直接送 | 放下后 |
| `pick` | 导航 → 识别 → 抓取 → 确认夹稳 → 收臂待命 | 夹稳后 |
| `place` | 带着物品回到交付处 → 放下 → 收臂 | 放下后 |

持物期间收到新的 `pick` 应拒绝；未持物收到 `place` 应拒绝。查询库存由网关本地完成，不涉及机器人。

### 等级四：位姿与视野

`detect` 回报中附带识别结果：

```json
{
  "taskId": "t_0002", "stage": "detect", "status": "done", "item": "aoliao",
  "perception": {
    "objects": [
      { "item": "aoliao", "confidence": 0.94, "bbox": [0.31, 0.42, 0.12, 0.18] },
      { "item": "pen_box", "confidence": 0.90, "bbox": [0.55, 0.20, 0.10, 0.12] }
    ],
    "target": "aoliao",
    "image": "data:image/jpeg;base64,/9j/4AAQ..."
  }
}
```

`bbox` 为归一化 `[x, y, w, h]`；`image` 可选，建议长边 640 像素、JPEG 质量 70。

位姿回报（新增可选接口）`POST /api/robot/pose`，执行中约 1 秒一次：

```json
{ "x": 2.31, "y": -0.42, "yaw": 1.57, "map": "booth", "ts": 1793546400500 }
```

数据来自 `Slam.get_curr_pose()`。另需提供一次展台地图的货架点和交付点坐标，用于画小地图。

## 3. 机器人侧接入示例（等级二起使用）

回报器在后台线程发送，网关不可达时直接丢弃，不阻塞运动控制：

```python
import json, queue, threading, time, urllib.request

class Reporter:
    def __init__(self, base_url: str):
        self.base = base_url.rstrip("/")
        self.q: queue.Queue = queue.Queue(maxsize=100)
        threading.Thread(target=self._run, daemon=True).start()

    def progress(self, task_id, stage, status, **extra):
        self._put("/api/task/progress", {"taskId": task_id, "stage": stage, "status": status,
                                         "ts": int(time.time() * 1000), **extra})

    def pose(self, x, y, yaw):  # 等级四
        self._put("/api/robot/pose", {"x": x, "y": y, "yaw": yaw, "ts": int(time.time() * 1000)})

    def _put(self, path, body):
        try:
            self.q.put_nowait((path, body))
        except queue.Full:
            pass

    def _run(self):
        while True:
            path, body = self.q.get()
            req = urllib.request.Request(self.base + path, json.dumps(body, ensure_ascii=False).encode(),
                                         {"Content-Type": "application/json"})
            try:
                urllib.request.urlopen(req, timeout=1).read()
            except Exception:
                pass  # 回报失败不影响任务
```

在现有流程里加几行（函数名以机器人程序实际为准）：

```python
reporter = Reporter("http://<网关IP>:4100")

navigate_to(location)                                   # 原有代码
reporter.progress(task_id, "navigate_to_shelf", "done", item=item)
objects, target = detect(item)                          # 原有代码
reporter.progress(task_id, "detect", "done", item=item,
                  perception={"objects": objects, "target": target})   # 等级四可选
grasp(target)                                           # 原有代码
reporter.progress(task_id, "grasp", "done", item=item)
navigate_to_delivery()                                  # 原有代码
reporter.progress(task_id, "navigate_to_delivery", "done")
place()                                                 # 原有代码
reporter.progress(task_id, "place", "done")
```

## 4. 兼容与安全

- 所有新增字段和接口都是可选的：网关没收到回报，界面自动退回 v1.1 的“执行中”显示；机器人不认识新字段，按 v1.1 处理。
- 回报异步发送、超时 1 秒、失败不重试，**不会让机器人等网关**。
- AI 只能选择技能和清单内的物品，不生成任何运动参数；技能结果以机器人回报为准，AI 不能自己声称完成。
- 等级三之前，确认取物的安全规则（无任务编号时不并发、无法确认接单时不重发、工作人员解除限制）全部沿用网关现有实现。
