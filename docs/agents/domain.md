# Domain docs

本文件是本项目领域文档布局与读取约定的唯一详细配置来源。

## Single-context 布局

本项目采用 single-context，覆盖 `apps/*` 和 `packages/*`：

- 根目录 `GLOSSARY.md`：共享领域词汇表。
- `docs/adr/`：架构决策记录。

pnpm 多包结构不意味着每个包分别维护领域上下文。
后续如需改为 multi-context，先确认领域边界与新布局，
不自动创建分包词汇表或 `GLOSSARY-MAP.md`。

## 探索前阅读

遵守 [AGENTS.md](../../AGENTS.md) 的通用工作规则与文档职责约定，
并阅读与任务相关的当前正式项目资料。

在探索代码、设计方案或编写涉及领域概念的内容之前：
1. 若根目录 `GLOSSARY.md` 存在，读取它。
2. 若 `docs/adr/` 存在，读取与本次任务相关的 ADR。

词汇表或 ADR 尚不存在时继续工作，
不因文件缺失预先创建空文件。
在术语或决策实际明确后，按需建立相关文档。

若实际发现其他领域布局或文档配置与本文件冲突，
先说明差异并请求确认，不静默切换布局。

## 使用领域词汇

输出中的领域概念沿用 `GLOSSARY.md` 的定义，
不擅自替换其明确排除的同义词。

遇到未定义概念时，先核对项目已有用语；
确有缺口时记录待解决事项，
不将推测写成已确认的领域定义。

## 尊重架构决策

方案与现有 ADR 冲突时，
明确指出相关 ADR、冲突内容及建议重新讨论的理由，
不得静默覆盖已有决策。

## 与其他共享规则的关系

当前资料、历史参考、临时文件及验证结论的使用边界，
沿用 [AGENTS.md](../../AGENTS.md)，本文件不重复这些详细规则。

涉及 Linear 或 Issue 内容时，
读取并遵守 `docs/agents/issue-tracker.md`。
