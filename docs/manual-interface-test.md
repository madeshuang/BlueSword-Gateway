# 联调前人工测试

Windows 本机练习优先双击根目录 `start-deepseek.cmd`（读取 `.env` 的 DeepSeek 配置）或 `start-gpt-relay.cmd`（读取 `.env.relay` 的 OpenAI 协议中转配置）。它会检查依赖与配置、构建网页，并同时启动下文的两个服务，打开4101主页面和4201人工工具。保持窗口开启，输入 `q` 后回车或按 Ctrl+C 同时停止。不需要再运行5173或另开网关；切换供应商前须先停止旧脚本。首次仍需安装依赖、配置所选 AI 的有效密钥；中转还需 `OPENAI_BASE_URL` 与 `OPENAI_MODEL`。脚本不沿用旧终端的 AI 变量，供应商服务异常仍会导致聊天失败，手选不受模型服务影响。

机器人团队通过 Git 拉取代码并连接真实设备时，先阅读[机器人团队联调指南](机器人团队联调指南.md)。本篇主要用于本机模拟自测；Git 获取的源码须先安装依赖并执行 `pnpm build`。

本指南用于你亲自模拟机器人一侧，检查网关发单、受理、完成和故障的接口。自动检查不能代替这些人工操作，也不能证明真实机器人动作。请先用本机人工对端完成下面的检查，再在真实机器人网络上核对双方地址和报文。

## 本机准备

解压交付包，在根目录执行 `pnpm install --frozen-lockfile`。包已包含构建网页；在开发工作区运行时先执行 `pnpm build`。

打开两个 PowerShell 终端，均进入项目根目录：

```powershell
# 终端一：人工机器人对端
pnpm manual:robot
```

```powershell
# 终端二：网关和网页
pnpm manual:gateway
```

分别打开网关 `http://127.0.0.1:4101` 和人工工具 `http://127.0.0.1:4201`。每次测试保持两个终端运行，结束时分别按 Ctrl+C。4101/4201 被占用时，先核对占用程序，不随意结束其他人的进程。

人工网关强制使用回环地址、示例目录、`.data/booth-manual.sqlite` 和4201人工对端，覆盖 `.env` 中的正式机器人地址和数据库设置。正式 `pnpm serve` 不受此模式影响。练习库存会跨重启保留，补满时仍按下述工作人员操作重置。人工模式的工作人员凭据固定为 `manual-local-only`，只适用于本机练习，不能作为正式环境凭据。

不需要 AI 密钥即可手动选品。如果聊天框显示“助手暂不可用，可直接选物品”，表示当前运行服务没有加载到所选供应商的密钥；手选、模拟思考展示和机器人接口仍可使用。需要聊天时，由启动负责人在本机 `.env` 中设置 `BOOTH_AI_PROVIDER` 及对应的有效密钥、模型，再停止并重新运行 `pnpm manual:gateway`。工作人员页面的“当前助手配置”可查看是否已配置凭据，但不能证明真实调用成功。人工模式仍读取所选 AI 的配置；若输入聊天消息，可能调用该供应商并产生费用。下面的接口检查使用手选，不需要调用模型。

## 工作人员操作速查

打开 `http://127.0.0.1:4101/#operations`，在“工作人员凭据”中输入本机练习凭据 `manual-local-only`。访客页面不显示固定入口，工作人员可以收藏这个地址。正式环境请使用实际网关地址加 `/#operations`，凭据由启动负责人在 `.env` 中设置 `BOOTH_OPERATOR_TOKEN` 后重启服务生效，不能沿用练习凭据。

物品选不了或不能继续加数量，可能是以下正常限制，请先看目录中的剩余数量和右上角状态：

- **库存不足或用完**：提交任务时已预留数量，完成后这些物品算作已取走。例如水初始3瓶，取完3瓶后就不能再选；库存保存在数据库中，重启服务和“开始新体验”都不会补满。需要补货后重置数量。
- **有任务未结束**：系统一次只执行一单，须等机器人通知完成。工作人员入口不能取消执行中的任务，不能用补货重置来解除占用。
- **故障或受理结果不明**：系统保留占用，避免机器人仍在执行时又发一单。须先核对机器人是否停止、物品是否被取走，再处理异常。

补货重置按以下步骤操作：

1. 实际使用时先补满所选物品，并核对页面显示的“补满后”目标；本机人工练习可将此步骤当作模拟补货。
2. 在“补货重置”区域选择“已补货物品”，确认当前剩余数量和补满目标。
3. 输入工作人员凭据，勾选该区域的“已核对并补满所选物品”，点击“重置所选物品库存”。只恢复所选物品，任务记录保留，其他页面同步更新。

整批补货时，在“已补货物品”中选择“全部物品”。页面会逐项显示当前剩余数量和补满目标；核对所有实物都已补满后，勾选“已核对并补满全部物品”，再点击“重置全部物品库存”。系统一次恢复目录中所有物品的配置数量，保留任务记录。只补了一种物品时仍选择单个物品，不使用全部重置。切换范围、任一物品数量变化或开始任务时，原有的全量勾选会取消，须重新核对。

重置成功后，凭据和补货勾选会自动清空，按钮再次变灰；下次操作须重新填写并确认。这是正常行为。刷新页面也不会保留凭据。

补货不需要勾选上方的“已现场核对机器人停止及物品情况”，也不用点击“解除本地占用”。那组控件仅用于异常：先现场核对，再勾选上方确认并点击“解除本地占用”；它不向机器人发送停止指令，也不恢复库存。如果还需补货，随后再按上面的补货步骤操作。有未结束任务或告警时，补货重置按钮会禁用。

## 逐项操作

| 场景 | 你的操作 | 应观察到的结果 |
| --- | --- | --- |
| 请求与受理 | 网关手选矿泉水1瓶并确认；切到人工工具，核对请求，再在120秒内点击“受理任务”。 | 原始记录中出现 `POST /api/task/dispatch`，请求体只含 `location`、`item`、`count`。点击前没有受理响应；点击后响应 `success:true`。网关保持取物中，聊天显示可折叠的模拟过程。 |
| 等待与完成 | 受理后先等十几秒，再点击“发送完成通知”。 | 等待期间不会自行完成。点击后发送 `POST /api/task/finished` 和 `{"result":"success"}`，收到网关回执；聊天结束思考并回复取好了。右上角保留已完成约10秒后恢复初始状态，聊天消息仍在。 |
| 拒绝 | 再选一单，人工工具点击“拒绝任务”。 | 受理响应为 `success:false`，网关显示未受理；这一单预留库存退回，没有完成回调。 |
| 故障 | 再选一单并受理，填写故障说明，点击“发送故障通知”。 | 原始记录显示 `POST /api/task/error`、`message` 和网关回执；网关显示异常并禁止新任务，不显示取好了。 |
| 异常核对与补货 | 打开网关 `http://127.0.0.1:4101/#operations`，用练习凭据核对解除异常；再核对并补满所选物品、重置库存。 | 解除异常本身不恢复数量。实际核对补满并重置后，所选物品恢复配置数量，任务记录保留。 |
| 全部补货 | 在“已补货物品”选择“全部物品”，逐项核对补满目标，模拟全部补货后填写凭据、勾选全量确认并重置。 | 所有物品恢复配置数量，另一页面同步更新，任务记录保留；成功后凭据及勾选清空。有任务或告警时不能操作。 |
| 重新启动 | 停止人工网关后重新运行，检查剩余数量。 | 库存不因重启补满；未确认任务仍占用。工具重启则清空工具自己的通信记录，因此先下载记录。 |

人工工具下方展示每次接口的时间、方向、URL、方法、请求头、原始 JSON、HTTP 状态码和响应体；敏感请求头会隐藏。`headersScope` 标明头部记录的范围：接收到的请求/回调响应记录实际头部，工具发出的回调请求/受理响应记录显式设置的头部，不包括 HTTP 自动补充字段。点击“下载本次接口记录 JSON”保存。该记录只包含机器人协议通信，不记录聊天模型请求，也不证明测试由人完成。最多保存本次运行最近200条。

如来不及在120秒内受理，连接可能已经断开。网关会保留受理不明，不能当作拒绝或重新发单；先按工作人员流程核对。回调发送失败时工具保留已受理状态，核对原始记录和网关状态后才能决定是否重试。当前协议没有任务关联标识，不要在下一单开始后重发上一单回调，限制见[任务关联说明](task-id-proposal.md)。

## 真实联调与公司主机

Windows 11 公司主机可以使用同一交付包。UU 远程用于操控、安装和启动，不能代替双方 HTTP 网络连通。笔记本带到公司后，可在主机或笔记本按本指南先测；这一步不用真实机器人。

真实联调前，向机器人团队核对任务接收地址、机器人可以访问的网关地址，以及接口路径和报文。将正式 `.env` 配好后运行 `pnpm serve`，不要运行人工入口。网关向机器人发单和机器人向网关回调必须都可达。现场同一局域网优先使用实际局域网 IP；异地需要另外落实双方可访问的网络通道。健康接口只能证明网关启动，不能证明机器人在线。按真实网络和机器人条件检查端口访问，不凭本机测试修改防火墙或认定公网已打通。
