# 初版演示交接与启动检查

适用范围：2026-10-12 向机器人团队演示我方初版、收集反馈。本地模拟器演示可以独立进行，不等待机器人团队全部开发完成。本文不是正式部署或机器人协议变更，接口仍以 [接口文档](接口文档.md) 为依据；未完成工作继续维护在 [开发计划](development-plan.md)。

## Windows PowerShell：日常启动入口

以下步骤使用仓库现有的 `pnpm dev:demo`。启动本身不会调用 AI；在页面发送对话才会产生真实 API 请求和费用。不要覆盖 `.env`、`.env.relay`，也不要删除数据库来清理任务。

### 1. 进入目录，检查端口

```powershell
Set-Location 'E:\Sevenova\BlueSword-Gateway'
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
    Where-Object { $_.LocalPort -in 4100,4200,5173 } |
    Select-Object LocalAddress,LocalPort,OwningProcess,
        @{Name='Process';Expression={(Get-Process -Id $_.OwningProcess).ProcessName}}
```

没有输出表示这三个端口目前没有监听。若有输出，先回到原启动终端确认服务用途：已有本项目演示可直接使用；需要重启时先在原终端按 Ctrl+C。不要直接结束不明进程，也不要另开一组 API 共用演示数据库。

首次使用需有 Node.js >=24.13.0、pnpm 11.25.0 和已安装依赖；缺少依赖时执行 `pnpm install --frozen-lockfile`，不升级锁文件。

### 2. 选择 DeepSeek，启动三个服务

先清除当前终端可能覆盖环境文件的供应商变量及 Node 预加载选项。此操作只影响当前终端，不修改文件或系统环境。

```powershell
Get-ChildItem Env: | Where-Object { $_.Name -match '^(OPENAI_|DEEPSEEK_|NODE_OPTIONS$)' } |
    ForEach-Object { Remove-Item -LiteralPath ('Env:' + $_.Name) }
$env:BOOTH_AI_PROVIDER = 'deepseek'
node --input-type=module -e 'import {readFileSync} from "node:fs"; import {parseEnv} from "node:util"; const e=parseEnv(readFileSync(".env","utf8")); console.log(e.DEEPSEEK_API_KEY?.trim() ? "DeepSeek 凭据存在且可读取" : "DeepSeek 凭据缺失");'
pnpm dev:demo
```

凭据检查只输出结果，不显示密钥；读文件失败时先核对文件权限。启动输出应分别显示 API、模拟器和 Vite 已监听。当前默认地址如下；若本机配置改过端口，以启动输出为准。

| 地址 | 用途 |
| --- | --- |
| `http://127.0.0.1:5173` | 在本机 Microsoft Edge 打开并操作的前端 |
| `http://127.0.0.1:4100/api/health` | 网关存活检查；不证明 AI 调用成功或机器人在线 |
| `http://127.0.0.1:4200` | 本地机器人模拟器监听地址，不是访客页面；接收模拟取物并发送模拟通知 |

`--simulator` 使用已有 `.data/booth-demo.sqlite` 和 `config/booth-catalog.example.json`；如设置过 `BOOTH_DEMO_DB_PATH` 或 `BOOTH_DEMO_CATALOG_PATH`，会采用指定文件。它会固定连接本机 4200，不连接真实机器人。已有占用必须核对原因，不能删库或把“开始新体验”当成取消任务。

### 3. 在页面核对，再正常停止

1. 页面能打开且默认展开的目录出现，只说明前端和网关快照可用。没有活动任务时，首次打开显示“等待你的选择”；有活动任务或告警时仍显示实际状态，不重播历史对话通知。商品列表可以独立滚动，也可手动折叠；不需要先展开才能选品。工作人员入口里的“网关状态同步正常”表示收到网关的状态事件，也不证明机器人在线。
2. 输入“这里有什么？”、接着问“你是谁”，应得到正常对话，不选品、不发单。AI 真实调用是否成功，以本次回复及后端 `ai_call` 日志的 `outcome:succeeded`、`structureValidated:true` 为据；仅有凭据或供应商 HTTP 200 不够。
3. 输入“请给我两瓶矿泉水”，检查候选与数量。只有亲自点击“确认取物”才发单；受理后显示“正在执行”，模拟器约 2.5 秒后通知才显示“已完成”。这是模拟任务完成，不是实际机器人完成。
4. 在运行 `pnpm dev:demo` 的终端按 Ctrl+C；如 PowerShell 提示终止批处理，确认终止。再执行第 1 步端口检查，确认 API、模拟器、前端均已停止。若有残留，只对已确认属于本次演示的 PID 执行 `Stop-Process -Id 具体PID`，不要批量结束所有 Node 进程。

前端修改可通过 Vite 热更新；若未更新，在 Edge 按 Ctrl+F5。API 没有自动重载，修改后端或供应商、工作人员凭据时需要停止并重启 API。

### 4. 备用：切换至 `.env.relay` 的 OpenAI 协议中转

先停止 DeepSeek 的 `pnpm dev:demo`，核对端口已释放。下面采用三个终端，避免 `dev:demo` 固定加载 `.env` 而覆盖备用配置。每个终端均先进入项目目录。

API 终端：

```powershell
Set-Location 'E:\Sevenova\BlueSword-Gateway'
Get-ChildItem Env: | Where-Object { $_.Name -match '^(OPENAI_|DEEPSEEK_|NODE_OPTIONS$)' } |
    ForEach-Object { Remove-Item -LiteralPath ('Env:' + $_.Name) }
$env:BOOTH_AI_PROVIDER = 'openai'
node --env-file=.env.relay --import tsx --input-type=module -e 'for (const n of Object.keys(process.env)) { if (n.startsWith("DEEPSEEK_")) delete process.env[n]; } process.argv.push("--simulator"); await import("./apps/api/src/booth/index.ts");'
```

模拟器终端执行 `pnpm dev:robot`；前端终端执行 `pnpm --filter @bluesword/web dev`。停止时在三个终端分别按 Ctrl+C，并检查端口。不要再同时启动 `pnpm dev:demo`。

Node 优先使用已有进程环境，所以切换前要清除旧的供应商变量。`.env.relay` 自身也包含 DeepSeek 字段，以上命令在读取它之后移除这些字段，再加载 API；OpenAI 地址、模型和密钥只采用该文件中的配置。配置在 API 启动时读取，必须重启才生效；前端不接触密钥。

本机已核对的备用 API 基址为 `https://vip.auto-code.net/v1`，配置模型为 `gpt-6-luna`；这是中转配置，不是官方 OpenAI 直连或底层模型身份的独立证明。该适配器使用 Responses 接口，供应商须支持 `/responses` 及结构化输出。`.env.relay` 必须继续被 Git 忽略，并保留仅本人和系统可读取的权限。`pnpm verify:relay` 是付费验证命令，不是启动命令，不应每次启动自动执行。

### 5. 工作人员凭据由服务负责人设置

当前本机没有配置 `BOOTH_OPERATOR_TOKEN`。入口仍可查看说明，但凭据输入和解除按钮被禁用；直接请求接口会返回 503“工作人员操作凭据尚未配置”。配置后仍需输入正确凭据，否则接口返回 403。不要在大屏分享凭据，不要把它写入前端、聊天或文档。

如确需演示异常收尾，由启动服务的负责人提供本地专用凭据。在 API 所在终端、启动之前输入；以下方式不把凭据写入命令历史，也不修改环境文件：

```powershell
$staffSecret = Read-Host '输入负责人提供的工作人员凭据' -AsSecureString
$env:BOOTH_OPERATOR_TOKEN = [System.Net.NetworkCredential]::new('', $staffSecret).Password
Remove-Variable staffSecret
# 随后按上面的 DeepSeek 或中转方式启动；使用完并停止服务后：
# Remove-Item Env:BOOTH_OPERATOR_TOKEN
```

凭据只授权工作人员解除故障、受理不明或全局告警造成的本地占用。必须先核对机器人停止及物品情况并勾选确认；执行中任务继续禁止解除。解除不发停止或取消指令，也不能证明机器人已停止或不会再回调。仅配置凭据不会放开执行中解除能力。

### 此前固定状态通知与布局检查（2026-10-12）

本轮只修改前端和对应浏览器回归，沿用上述工作区基线。左侧保持访客对话；右侧依次展示 `SERVICE MOMENT`、物品浏览和取物确认，窄屏按相同阅读顺序纵向排列。独立装饰区及宣传文字已移除，原机器人插画缩小放在任务卡内，商品 SVG/CSS 素材继续保留。目录展开后可能需要向下滚动确认，也可以收起目录查看候选。

对话里的“取物通知”是固定系统事件，仅根据网关已确认的状态变化显示，不调用 AI。点击确认、动画和等待时长不能触发受理或完成通知；只有状态进入执行或完成才显示对应通知。故障、受理不明、人工处理及全局告警均采用明确文案，不代表机器人已停止。

同一页面生命周期内，以内部任务 ID 和状态去重；初次加载仅建立快照基线，不重播历史状态。SSE 重连或相同状态的重复回调不会刷屏。HTTP 快照请求期间若收到更新的 SSE，较旧的 HTTP 响应不再覆盖页面，避免完成后退回执行中。“开始新体验”清空可见对话，但保留任务去重记录及原任务，之后发生的实际完成或故障仍会提示。固定事件在发送聊天请求之前被过滤，不进入模型历史；迟到 AI 回复通过原体验版本保护，并采用追加方式保留同时到达的状态事件。正式机器人报文、SQLite 状态和 P3 回调事务没有改动。

执行命令为 `pnpm test`、`pnpm build`、`pnpm test:browser`。常规 45 项测试、严格类型检查及生产构建通过；[浏览器回归源码](../scripts/booth-acceptance.cjs) 通过本地可控 HTTP 对端、真实网关快照和 SSE 检查受理前不播报、完成前不显示完成、重复回调、原生 EventSource 重连、迟到 HTTP 不覆盖完成状态、等待不刷屏、新体验隔离和 AI 历史排除，并检查五种视口、触摸和键盘操作。重连用例主动结束一次 SSE 响应，再让浏览器原生重连至网关；所有帧均取自网关实际快照，没有制造任务状态。开发服务重启后仍建议刷新页面，不把代理连接表现当成机器人状态证明。

本轮没有发送真实模型请求；此前七项真实 DeepSeek 对话结果未重跑。浏览器中的十次聊天操作全部使用可控响应，仅验证交互；任务状态变化额外产生的模型请求为零。真实机器人及现场可靠性继续等待联调，本地模拟结果不能替代它们。

## 初版决策清单

### 我方可以自行确定

采用当前实现作为初版默认：单进程 SQLite；人工确认后发单；模型超时 20 秒、机器人受理等待 8 秒；提醒阈值 120 秒且可配置。提醒时间是我方展示参数，不等于机器人正常时长或强制结束条件。日志、事务、前端过期结果保护、凭据缺失提示和配置校验无需等对方开发。基本供应商选择与自动故障切换分开，后者继续留作增强项。

我方工作人员流程也可以确定：故障或受理不明保持占用，要求现场确认停止及物品情况、专用操作凭据和明确勾选；执行中不提供取消。此流程只改变我方状态，不能替机器人完成停止或停止回调重发。

### 无须改变报文的临时业务约束

本地演示采用模拟器，可以连续体验。真实机器人首次联调先限定单任务，并在异常时暂停后续任务、人工核对；不自动重发下发指令，不依靠固定等待时长宣布收尾。真实目录、地址和网络必须核对后才打开发单准入。

这些约束降低操作风险，但无 taskId 时仍无法区分上一单通知与下一单通知。串行和人工核对均不能修复 P1；在确认关联协议前，不把连续真实多单运行视为已验收。

## 语音输入：非阻塞评估

最小方案是一个默认关闭的浏览器可选控件：用户点击麦克风后进行单次中文识别，把最终文本作为可编辑草稿交给现有输入框；用户再点发送生成建议，最后仍独立确认取物。识别结果不得调用聊天提交或发单函数。输入被编辑、开始新体验、正在提交或组件卸载时终止识别，迟到结果不得覆盖新草稿；拒绝权限、无声音、不支持或识别失败时回退文字输入。

[MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition) 标明兼容性有限，部分浏览器会把音频发往服务端，不能把“浏览器原生”当作完全离线。[设备内识别说明](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API) 还涉及语言包及权限策略。展会噪声、物品名称/数量误识别、服务网络、真实麦克风权限和手机兼容性都可能影响演示。

本机 Edge 155.0.4283.45 在回环页面上检测到识别构造器、processLocally 属性、available 方法和麦克风 API；仅检测接口存在，随后保持离线，没有请求麦克风、执行识别或下载语言包。中文语言包、离线效果及识别准确率仍未验证。

结论：可以设计为可选实验控件，但本次不合入语音功能。要证明现场可用仍需要真实设备、语言包与麦克风验证，而当前没有这些证据；采用浏览器默认远端识别也会引入未核实的服务处理。初版以文字交互交付，周一演示后再评估。没有新增 Whisper、上传接口、语音服务或付费调用。
