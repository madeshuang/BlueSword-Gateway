# 本机人工联调指南

本指南用于 Windows 下的本机人工练习。人工机器人工具代替真实机器人接收任务，通过点击按钮决定是否接单，再发送完成或故障通知。

首次使用先按 [README 第 1、2 节](../README.md#1-获取代码与安装依赖) 获取代码、安装依赖并配置 AI，再从本指南第 1 节开始操作。以下操作均在项目根目录进行。

## 1. 配置 .env

人工入口读取根目录 `.env` 中的 [AI 配置](../README.md#2-配置-ai)，以及下面的任务等待提醒时间：

```dotenv
BOOTH_TASK_REMINDER_MS=120000
```

`BOOTH_TASK_REMINDER_MS` 的单位是毫秒，`120000` 表示 2 分钟。从网关建立取物任务起计时，接单后继续累计，不重新开始。累计等待达到所设时长时，页面显示“等待时间较长，请联系工作人员核对”。

网关确认机器人拒绝任务、收到完成或故障通知，或工作人员解除本单的新任务限制后，停止本单的等待计时和提醒。接单回复超时、无法确认是否接单时，仍继续计时。收到故障通知后会改为异常提示，仍需按下文处理。

等待提醒只提示联系工作人员，不会自动结束任务或解除新任务限制。初次练习可保留默认值。

`.env` 中的其他配置项由 `start-local.cmd` 自动设置，实际使用的值如下，无需手动修改：

| 配置项                       | 人工练习实际使用的值与作用                                                   |
| ------------------------- | --------------------------------------------------------------- |
| `PORT`                    | `4101`，网关端口。                                                    |
| `BOOTH_HOST`              | `127.0.0.1`，仅供本机访问。                                             |
| `BOOTH_ROBOT_MODE`        | `simulator`，连接人工机器人工具。                                          |
| `ROBOT_DISPATCH_URL`      | `http://127.0.0.1:4201/api/task/dispatch`，向本机 4201 端口的人工工具发送任务。 |
| `ROBOT_TIMEOUT_MS`        | `120000`，等待人工点击接受或拒绝任务，最长 120 秒。                                |
| `BOOTH_CATALOG_PATH`      | `config/booth-catalog.example.json`，使用示例物品清单。                   |
| `BOOTH_CATALOG_CONFIRMED` | `true`，允许使用这份练习清单发单。                                            |
| `BOOTH_DB_PATH`           | `.data/booth-manual.sqlite`，保存人工练习的任务和库存。                       |
| `BOOTH_OPERATOR_TOKEN`    | `manual-local-only`，人工练习的工作人员凭据。                                |

这些设置只在本次进程中生效，不改写 `.env`。因此，即使 `.env` 中保留着真实机器人的地址和数据库路径，人工入口也会使用表中的配置。人工练习的数据库与真实联调默认使用的 `.data/booth.sqlite` 分开，重启后各自保留任务和库存。

## 2. 一键启动与停止

先停止其他本机人工练习服务，再双击根目录的 **`start-local.cmd`**。脚本会检查类型、构建网页，启动网关和人工工具，并打开两个页面：

| 本机地址                                | 用途                            |
| ----------------------------------- | ----------------------------- |
| `http://127.0.0.1:4101/`            | 网关主页面：AI 对话、选择物品、确认取物和查看任务状态。 |
| `http://127.0.0.1:4201/`            | 人工机器人工具：接受或拒绝任务，发送完成或故障通知。    |
| `http://127.0.0.1:4101/#operations` | 工作人员页面：处理异常和补货重置。             |

`start-local.cmd` 内部调用了 `scripts/start-local.cjs`，如果习惯使用终端，也可以在项目根目录执行以下命令，两种启动方式任选其一：

```powershell
node scripts/start-local.cjs
```

两种方式启动成功后，都会自动打开网关主页面和人工机器人工具页面。双击启动方式还会自动切换到项目根目录，并在启动失败时暂停窗口，方便查看错误提示。

启动后，先在网关主页面发送一条聊天消息，确认 AI 能正常回复。如果显示“助手暂未配置，可直接选物品”，请核对 `.env` 中所选服务的密钥；提示“助手暂不可用”时，核对该服务的配置和网络。修改后重启，再验证回复。

联调期间保持启动窗口开启。结束时在窗口中输入 `q` 后回车，或按 Ctrl+C，同时停止两个服务。修改配置后也应先停止，再重新启动。若端口被使用，先到原来的启动窗口停止旧服务，不要重复启动。

## 3. 走通一次人工联调

此时网关连接的是本机人工工具。需要在两个页面之间切换，分别完成用户取物和机器人回复的操作。

人工入口将 `ROBOT_TIMEOUT_MS` 固定为 `120000`，即 120 秒，用于等待人工工具回复是否接单。从网关下发任务起计时；收到完整回复，或请求出错、超时后，这次等待结束。不要求在这 120 秒内完成取物。

接单回复时限与 `BOOTH_TASK_REMINDER_MS` 独立。虽然人工练习中两者默认都是 120 秒，但修改等待提醒时间不会改变点击接受或拒绝任务的时限。

1. 在网关主页面（4101）通过聊天让 AI 推荐一件有库存的物品，检查推荐的物品和数量，再点击“确认取物”。只有确认后，网关才会下发任务；页面也支持直接手选物品。
2. 切到人工机器人工具（4201），查看收到的任务，核对物品、位置和数量，并在 **120 秒内**点击“接受任务”。这一步表示机器人接受了任务，网关页面应继续等待取物结果。
3. 接单后先等几秒，确认网关不会自行完成，再在人工工具中点击“发送完成通知”。检查工具是否收到网关确认已接收通知的回复，以及网关页面是否显示取物完成。右上角的完成状态应保留约 10 秒后复位，聊天和任务记录仍保留。

等待期间，网关可能显示出发、抓取、返回等文字，这些是预设的模拟展示。只有在人工工具中发送完成通知后，这次模拟任务才会完成。

### 检查其他场景

以下检查使用手动选品即可，无需调用 AI。拒绝和故障须分别新建任务测试；补货和异常处理按下一节操作。

| 操作                            | 应观察到的结果                                                  |
| ----------------------------- | -------------------------------------------------------- |
| 发单后点击“拒绝任务”                   | 网关显示机器人未接单，本单预留的数量退回可用库存，无需发送完成通知。                       |
| 接单后填写故障说明，点击“发送故障通知”          | 工具收到网关确认已接收通知的回复；网关显示异常并阻止新任务，不显示取物完成。                   |
| 现场核对后解除新任务限制，再分别测试单个物品和全部物品补货 | 解除限制不恢复库存；补货重置后，对应物品恢复到补满目标，另一页面同步更新，任务记录保留。有任务或告警时不能重置。 |
| 正常停止并重新启动网关                   | 库存和任务记录保留，未结束的任务仍会阻止新任务，网关也不会自动重发原任务。                    |

### 无法继续取物时

如果你在人工工具中发送了故障通知，或者没有及时点击“接受任务”，网关会暂不接受新的取物任务，等待工作人员核对处理。多次完成取物后，也可能遇到库存不足。这些情况需要到工作人员页面处理。

工作人员凭据是操作口令，用于核实是否有权解除新任务限制或重置库存。打开工作人员页面，在“工作人员凭据”栏输入本机练习凭据 **`manual-local-only`**，再根据页面状态操作：

- **故障或无法确认机器人是否接单**：先核对模拟任务和物品情况，确认可以结束本次练习任务后，勾选“已现场核对机器人停止及物品情况”，点击“解除新任务限制”，允许网关接收新任务。这个按钮不会向机器人发送停止或取消指令，也不会恢复库存，不能用于取消执行中的任务。
- **库存不足**：本机练习时可以模拟补货。在“补货重置”中选择需要补货的物品，或选择全部物品，核对页面显示的补满目标，勾选相应的补货确认，再重置库存。如果还有未结束的任务或告警，需要先处理，才能重置。

补货成功后，凭据和补货勾选会清空，下次操作须重新填写并确认。切换补货范围、库存变化或开始新任务后，也须重新核对并勾选。

本机库存和任务记录保存在 `.data/booth-manual.sqlite` 中。点击“开始新体验”只清空本页对话和选择，不取消后台任务，也不解除新任务限制；重启服务或开始新体验都会保留已有库存，因此需要补货时仍应使用上述操作，不要删除数据库来解除限制。

### 保存接口记录

人工工具下方的“原始接口记录”会显示网关发来的任务、工具发送的完成或故障通知，以及双方的回复。操作失败时，可以在这里查看发了什么、对方如何回复。

需要保存时，点击“下载本次接口记录 JSON”，保存下载的文件，可以补充记录刚才做了什么、页面出现了什么提示。工具只保留本次运行最近 200 条通信，重启后清空，请在停止工具前下载。

这些记录不包含 AI 请求，也不能证明真实机器人完成了动作。
