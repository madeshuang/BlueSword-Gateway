# 本机人工联调指南

本指南用于 Windows 下的本机人工练习。人工机器人工具代替真实机器人接收任务，通过点击按钮决定是否接单，再发送完成或故障通知。

首次使用先按 [README 第 1 至 3 节](../README.md#1-获取代码与安装依赖) 获取代码、安装依赖并配置文字 AI 和语音输入，再从本指南第 1 节开始操作。以下操作均在项目根目录进行。

## 1. 配置 .env

人工入口读取根目录 `.env` 中的 [AI 配置](../README.md#2-配置-ai)、[语音输入配置](../README.md#3-配置语音输入)，以及下面的任务等待提醒时间：

```dotenv
BOOTH_TASK_REMINDER_MS=120000
```

`BOOTH_TASK_REMINDER_MS` 的单位是毫秒，`120000` 表示 2 分钟。从网关建立取物任务起计时，接单后继续累计，不重新开始。累计等待达到所设时长时，页面显示“等待时间较长，请联系工作人员核对”。

网关确认机器人拒绝任务、收到完成或故障通知，或工作人员解除本单的新任务限制后，停止本单的等待计时和提醒。接单回复超时、无法确认是否接单时，仍继续计时。收到故障通知后会改为异常提示，仍需按下文处理。

等待提醒只提示联系工作人员，不会自动结束任务或解除新任务限制。初次练习可保留默认值。

### 选择练习物品清单

人工模式默认加载 `config/booth-catalog.example.json` 中的现场 11 种物品，无需额外配置。每种物品的初始库存及补满目标均为 3，位置保留“待配置”，人工工具允许用它练习。

需要另用一份练习清单时，才在根目录 `.env` 中填写相应路径，例如：

```dotenv
BOOTH_MANUAL_CATALOG_PATH=config/booth-catalog.practice.json
```

上面的自定义文件需要自行准备；不填写此项即可使用默认的 11 种物品。修改清单或路径后，需停止并重新启动服务。

`BOOTH_MANUAL_CATALOG_PATH` 只影响人工模式；真实模式继续读取 `BOOTH_CATALOG_PATH`。切换练习清单不会删除历史任务或重置已有库存。若测试需要统一起始数量，先按下文的补货操作恢复到清单中的目标，不要删除数据库。

下表中的配置项由 `start-local.cmd` 自动设置，无需手动修改：

| 配置项                       | 人工练习实际使用的值与作用                                                   |
| ------------------------- | --------------------------------------------------------------- |
| `PORT`                    | `4101`，网关端口。                                                    |
| `BOOTH_HOST`              | `127.0.0.1`，仅供本机访问。                                             |
| `BOOTH_ROBOT_MODE`        | `simulator`，连接人工机器人工具。                                          |
| `ROBOT_DISPATCH_URL`      | `http://127.0.0.1:4201/api/task/dispatch`，向本机 4201 端口的人工工具发送任务。 |
| `ROBOT_TIMEOUT_MS`        | `120000`，等待人工点击接受或拒绝任务，最长 120 秒。                                |
| `BOOTH_CATALOG_PATH`      | 读取上面的 `BOOTH_MANUAL_CATALOG_PATH`；留空时使用 `config/booth-catalog.example.json`。 |
| `BOOTH_CATALOG_CONFIRMED` | `true`，允许使用这份练习清单发单。                                            |
| `BOOTH_DB_PATH`           | `.data/booth-manual.sqlite`，保存人工练习的任务和库存。                       |
| `BOOTH_OPERATOR_TOKEN`    | `manual-local-only`，人工练习的工作人员凭据。                                |

这些设置只在本次进程中生效，不改写 `.env`。因此，即使 `.env` 中保留着真实机器人的地址和数据库路径，人工入口也会使用表中的配置。人工练习的数据库与真实联调默认使用的 `.data/booth.sqlite` 分开，重启后各自保留任务和库存。

## 2. 一键启动与停止

先停止其他本机人工练习服务，再双击根目录的 **`start-local.cmd`**。脚本会检查类型、构建网页，启动网关和人工工具，并自动打开这两个服务的主页面。常用地址如下：

| 本机地址                                | 用途                            |
| ----------------------------------- | ----------------------------- |
| `http://127.0.0.1:4101/`            | 网关主页面：AI 对话、选择物品、确认取物和查看任务状态。 |
| `http://127.0.0.1:4201/`            | 人工机器人工具：接受或拒绝任务，发送完成或故障通知。    |
| `http://127.0.0.1:4101/#operations` | 工作人员页面：处理异常和补货重置。             |
| `http://127.0.0.1:4101/developer/speech` | 语音识别记录：查看识别结果、状态和等待时间，下载 JSON。 |
| `http://127.0.0.1:4101/developer/robot` | 机器人通信记录：查看网关与人工工具实际收发的接口报文，下载 JSON。 |

`start-local.cmd` 内部调用了 `scripts/start-local.cjs`，如果习惯使用终端，也可以在项目根目录执行以下命令，两种启动方式任选其一：

```powershell
node scripts/start-local.cjs
```

两种方式启动成功后，都会自动打开网关主页面和人工机器人工具页面。双击启动方式还会自动切换到项目根目录，并在启动失败时暂停窗口，方便查看错误提示。

启动后，先在网关主页面发送一条聊天消息，确认 AI 能正常回复。如果显示“助手暂未配置，可直接选物品”，请核对 `.env` 中所选服务的密钥；提示“助手暂不可用”时，核对该服务的配置和网络。修改后重启，再验证回复。

联调期间保持启动窗口开启。结束时在窗口中输入 `q` 后回车，或按 Ctrl+C，同时停止两个服务。修改配置后也应先停止，再重新启动。若端口被使用，先到原来的启动窗口停止旧服务，不要重复启动。

### 大屏展示

需要在大屏练习时，建议先将浏览器缩放设为 100%，再按 F11 全屏；再次按 F11 可退出并切换到人工机器人工具。页面根据可用窗口空间调整布局，物品列表可滚动浏览。

### 本机录音与其他设备访问

在本机录音时，使用 `http://localhost:4101/` 或 `http://127.0.0.1:4101/` 打开主页面，并允许浏览器使用麦克风。语音操作方式见 [README 的语音输入说明](../README.md#语音输入使用方式)。

人工入口只监听本机回环地址，其他设备不能直接访问。跨设备录音既需要设备能够访问网关，也需要浏览器信任的 HTTPS 页面和麦克风权限；通过局域网 IP 访问 HTTP 页面通常不能录音。目前人工入口还未提供这种跨设备访问方式，项目也尚未完成现场 HTTPS 部署。这些是网页访问和录音的条件，不改变机器人原有的 HTTP 接口。

### 查看和下载运行记录

运行记录页面分为“语音识别记录”和“机器人通信记录”，主界面没有入口，可直接打开表中的地址。输入本机练习口令 `manual-local-only`，点击“读取／刷新”查看记录，再按需点击“下载 JSON”。读取和下载都需要校验口令；页面只在当前内存中使用口令，不会将它放入网址或浏览器持久存储。

语音识别记录包含供应商、模型、识别原文、等待时间及失败或取消状态，并将识别原文与用户实际发送给文字 AI 的内容分别记录，不保存原始录音。机器人通信记录保存发单、完成通知和故障通知的实际请求与回复，隐藏凭据请求头；单个正文超过 32 KiB 时，只保留开头并标明截断。

两类记录保存在 `.data/booth-manual.sqlite` 中，各保留最近 200 条，重启后保留；超过上限后，最早的记录会被自动删除。需要长期留存时可下载 JSON。人工工具自身的临时接口记录与这里的网关记录分别保存，区别见下文[保存接口记录](#保存接口记录)。连接失败不能证明请求没有送达，这些记录也不能证明真实机器人执行了动作；历史语音实验结论仍以各自的日期和环境为限。

## 3. 走通一次人工联调

此时网关连接的是本机人工工具。需要在两个页面之间切换，分别完成用户取物和机器人回复的操作。

人工入口将 `ROBOT_TIMEOUT_MS` 固定为 `120000`，即 120 秒，用于等待人工工具回复是否接单。从网关下发任务起计时；收到完整回复，或请求出错、超时后，这次等待结束。不要求在这 120 秒内完成取物。

接单回复时限与 `BOOTH_TASK_REMINDER_MS` 独立。虽然人工练习中两者默认都是 120 秒，但修改等待提醒时间不会改变点击接受或拒绝任务的时限。

在聊天输入框中输入需求时，也可以使用语音输入，再检查或修改识别文字后发送。

1. 在网关主页面（4101）通过聊天让 AI 推荐一件有库存的物品，或直接手选，核对物品和数量后点击“确认取物”。只有确认后，网关才会下发任务。
2. 切到人工机器人工具（4201），查看收到的任务，核对英文编码、位置和数量，并在 **120 秒内**点击“接受任务”。例如，扑克牌的编码为 `playing_card_box`，圆珠笔为 `pen_box`。这一步表示机器人接受了任务，网关页面应继续等待取物结果。
3. 接单后先等几秒，确认网关不会自行完成，再在人工工具中点击“发送完成通知”。检查工具是否收到网关确认已接收通知的回复，以及网关页面是否显示取物完成。右上角的完成状态应保留约 10 秒后复位，聊天和任务记录仍保留。

等待期间，网关可能显示出发、抓取、返回等文字，这些是预设的模拟展示。只有在人工工具中发送完成通知后，这次模拟任务才会完成。

### 检查其他场景

以下检查使用手动选品即可，无需调用 AI。上面的单件流程已覆盖表中第一种组合，继续检查其余两种即可。选择库存充足、单品每单上限允许的物品，每次都完成上一单后，再开始下一次：

| 选择方式 | 人工工具应收到的任务 |
| --- | --- |
| 一种物品一件 | `items` 中一项，`count` 为 1。 |
| 同一种物品两件 | `items` 中一项，`count` 为 2。 |
| 两种物品各一件 | `items` 中两项，`count` 各为 1；一次发送完整清单，不拆成两单。 |

拒绝和故障须分别新建任务测试；补货和异常处理见后文：

| 操作                            | 应观察到的结果                                                  |
| ----------------------------- | -------------------------------------------------------- |
| 发单后点击“拒绝任务”                   | 网关显示机器人未接单，退回本单预留的数量；期间已经补货重置过的物品，不再加回旧数量。无需发送完成通知。 |
| 接单后填写故障说明，点击“发送故障通知”          | 工具收到网关确认已接收通知的回复；网关显示异常并阻止新任务，不显示取物完成。                   |
| 等待接单、已接单、故障或无法确认接单时，按后文核对并解除新任务限制 | 原任务显示“工作人员已处理”，等待提醒消失，可以继续接收新任务；库存和历史保留。 |
| 检查完成后正常停止并重新启动服务 | 库存和任务记录保留。如果仍有未结束的任务，网关不能自动重发或认定完成；重启前尚未确认是否接单的任务，需要工作人员核对。 |

### 检查等待期间的补货

分别检查“等待人工工具回复是否接单”和“已接单、尚未收到完成通知”时的补货。以下以默认清单中的扑克牌、圆珠笔为例；使用自定义清单时，替换为相应物品和补满目标。补货方法见后文“无法继续取物时”，本机练习可以模拟实物补满。

1. 先将两种物品的数量分别重置到目标 3。
2. 确认两种物品各取一件，页面应分别剩余 2 件。先不要在人工工具中接单，只补货重置扑克牌，检查扑克牌恢复为 3、圆珠笔仍为 2，当前任务仍未结束，下一单仍不能提交。这一步须在 120 秒接单回复时限内完成。
3. 在人工工具中点击“拒绝任务”，检查扑克牌保持 3、圆珠笔恢复为 3，扑克牌不能变成 4。
4. 另建一单并点击“接受任务”，先不发送完成通知。模拟全部实物补满后，重置全部库存，检查各物品恢复到目标，原任务仍限制新任务；最后再点击“发送完成通知”。

### 无法继续取物时

如果人工工具尚未回复接单、接单后没有发送完成通知，或发送了故障通知，网关会暂不接受新的取物任务。练习结束后仍有旧任务时，可以到工作人员页面核对处理。多次完成取物后，也可能需要补货。

工作人员凭据是操作口令，用于核实是否有权解除新任务限制或重置库存。打开工作人员页面，在“工作人员凭据”栏输入本机练习凭据 **`manual-local-only`**，再根据页面状态操作：

- **处理未结束的旧任务**：无论页面显示等待接单、已接单、故障还是无法确认接单，先核对模拟任务和物品情况，确认可以结束本次练习后，勾选“已现场核对机器人停止及物品情况”，点击“解除新任务限制”。人工工具同步结束旧练习，恢复“等待网关发来任务”；原任务显示“工作人员已处理”，等待提醒消失，随后可以正常提交下一单。无需为了继续练习而给旧任务补发完成或故障通知。这个操作不代表取物完成，也不会恢复库存。如果任务或告警发生变化，须针对更新后的内容重新核对并勾选。
- **库存不足**：本机练习时可以模拟补货。在“补货重置”中选择需要补货的物品，或选择全部物品，核对页面显示的补满目标，勾选相应的补货确认，再重置库存。即使旧任务未结束或有告警，也可核对后补货；但原任务限制仍保留。

补货成功后，凭据和补货勾选会清空，下次操作须重新填写并确认。切换补货范围或相关库存变化后，也须重新核对并勾选。

若人工工具连接失败，网关会提示错误并保留旧任务限制，请恢复工具连接后重新核对。若工具正在发送完成或故障通知，先等这次通信结束再核对；不能在发送期间强行结束旧练习。人工工具页面每秒刷新，看到“等待网关发来任务”后再开始下一次练习。

本机库存和任务记录保存在 `.data/booth-manual.sqlite` 中。点击“开始新体验”只清空本页对话和选择，不取消后台任务，也不解除新任务限制；重启服务或开始新体验都会保留已有库存，因此需要补货时仍应使用上述操作，不要删除数据库来解除限制。

### 保存接口记录

人工工具下方的“原始接口记录”会显示网关发来的任务、工具发送的完成或故障通知，以及双方的回复。本机练习中，工作人员结束旧练习的通信也会单独记录。操作失败时，可以在这里查看发了什么、对方如何回复。

需要保存时，点击“下载本次接口记录 JSON”，保存下载的文件，可以补充记录刚才做了什么、页面出现了什么提示。工具只保留本次运行最近 200 条通信，重启后清空，请在停止工具前下载。

这些记录不包含 AI 请求，也不能证明真实机器人完成了动作。
