# 剩余物品数量与补货重置

本说明介绍当前库存及补货规则。库存持久化保存，重启服务后保留剩余数量；工作人员实际补货并核对后，手动将所选物品重置到配置数量。它是我方对已提交取物数量的记录，不是机器人实时盘点。

## 数量规则

目录中的 `maxCount` 继续表示每单上限，新增 `initialStock` 表示首次建立库存及补货重置后的数量。示例目录先采用矿泉水 3、小面包 3、纪念品 2、蔬菜礼盒 1。`initialStock` 必须是 0 至 100000 的整数；现场目录也须补充该字段。它可以与每单上限不同。

页面和 AI 使用 `availableCount`，即当前可以分配给下一单的数量。它已经扣除未结束任务的预留。一次选择同时受到每单上限和可用数量限制。例如水初始为 3，确认取 2 瓶后，可用数量变成 1；后一单不能再取 2 瓶。

| 事件 | 数量处理 |
| --- | --- |
| 首次确认取物 | 在同一数据库事务中检查可用数量、预留数量并建立任务；不足时拒绝，不向机器人发单。 |
| 相同请求标识再次核对 | 返回原任务，不再次预留；参数或体验不匹配仍按原规则拒绝。 |
| 机器人明确回复未受理 | 将预留退回，与拒绝状态一起提交。 |
| 收到完成通知 | 预留数量成为已取数量，不再次扣减；重复通知不再次改变数量。 |
| 受理不明、不可恢复故障或工作人员解除占用 | 不自动退回数量，因为无法确定物品是否已经被取走。工作人员核对物品情况并补满后，再重置库存。 |
| 重启服务 | 保留数据库数量及任务占用，不自动补满或重新发单。 |

首次启用本功能时，尚无库存记录的物品按 `initialStock` 初始化；如存在历史未结束任务，会先扣除该任务数量，最低为零。历史完成记录没有补货信息，因此不能据此猜测当前实物数量。负责人首次启用前须核对现场物品。后续修改配置只改变新物品的初始化数量及下一次重置目标，不覆盖已有库存记录。

## 聊天与手动选择

每次模型请求均提供当前可用数量，并要求模型解释超量限制、不擅自缩小用户提出的数量。模型回复回来后，后端再次核对最新库存；如建议已超量，返回正常的数量不足说明和 `selection:null`，不选择较小数量，也不发单。提示词和后端检查适用于 OpenAI 与 DeepSeek。

手选目录直接显示剩余数量。加号不能超过当前可用数量与每单上限；售罄物品不能选择。已经选定的数量如果因为其他任务而过时，页面保留原数量、提示重新确认并禁止提交，不悄悄改小。后台提交仍独立检查数量，不能通过旧页面或直接 HTTP 请求绕过。待核对的原请求仍可用原标识核对，不能因它已预留库存而被前端错误阻止。

## 工作人员补货

工作人员入口沿用页面地址的 `/#operations`。在“补货重置”区域选择实际已补货的物品，核对显示的补满目标，输入工作人员凭据并勾选“已核对并补满所选物品”，再点击“重置所选物品库存”。

该操作沿用 `BOOTH_OPERATOR_TOKEN`，凭据不写入页面存储或状态快照。没有凭据、没有现场确认、存在未结束任务或全局告警时，不能重置。切换物品、库存或补满目标变化，以及出现任务或告警时，页面撤销原来的补货勾选，要求重新核对。异常处理和补货是两件操作：解除本地占用不会改变库存。成功重置仅更新所选物品数量，保留任务记录，并经 SSE 同步到其他页面；审计记录包含物品及重置前后数量。

整批补货时，“已补货物品”新增“全部物品”选项，展示所有物品的当前数量和补满目标；须单独勾选“已核对并补满全部物品”，再点击“重置全部物品库存”。全量重置使用同一工作人员凭据及任务、告警限制，在一个 SQLite 事务中恢复整个当前目录，逐项保留数量审计；任何一步写入失败则整体回滚，成功提交后才同步页面。单个重置继续保留。切换范围、任一库存变化或任务开始都会撤销全量确认。重置成功后凭据和补货勾选清空，下次须重新填写与核对。

新增我方内部接口如下，不改变机器人侧的三项接口及报文：

```http
POST /api/booth/operator/stock/reset
Content-Type: application/json
X-Operator-Token: <工作人员凭据>
```

```json
{"productId":"water","confirmation":"已核对并补满库存"}
```

成功返回当前网页快照；未配置凭据返回 503，凭据错误返回 403，物品或确认内容错误返回 400，有未结束任务或告警返回 409。数量写入与审计记录在同一事务中完成，事务提交后再发布状态。

全部重置使用 `POST /api/booth/operator/stock/reset-all`，请求头沿用上面的凭据和 JSON 格式，请求体为 `{"confirmation":"已核对并补满全部库存"}`；单个重置的确认文字不能用于此接口。状态码含义相同，不需要向机器人发送补货接口。
