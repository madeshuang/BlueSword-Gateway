# AI 取物进度最小版本与验证记录

2026-10-14，基线 `a0a268d` 之后的本批工作区。验证使用真实本地网关、SQLite、浏览器及受控 AI/机器人 HTTP 对端；没有调用真实模型或机器人。

## 本次实现

`POST /api/booth/experiences` 返回独立体验的 `id` 和随机凭据。凭据只保存在当前标签页的 `sessionStorage`，后端仅保存其 SHA-256 摘要；不进入共享快照、日志或模型输入。确认取物和聊天通过 `X-Booth-Experience` 携带凭据，后端查验后使用关联任务的 `BoothTask.id`，不接受客户端声明的任务状态或公开任务 ID 来认领任务。

首次发单时，在原有 SQLite 事务中一并保存任务、防重记录和体验归属。相同 `requestId` 必须使用原体验重试；其他体验或无凭据调用不能接管已归属的任务。一次体验关联最近一次确认的任务，旧任务重试不会把关联退回旧单。旧版无凭据任务可以按原方式核对，但不能事后认领。

同一标签页刷新恢复凭据；新页面导航和“开始新体验”创建新关联，不删除后台任务。独占浏览器锁补充防止复制标签页共用凭据。当前实现需要支持 Web Locks 的安全上下文（如本机 localhost 或 HTTPS）；不支持或存储失败时禁止发单，聊天仍可提供建议，但无法确认个人进度。关闭标签页再从书签打开会建立新体验，不恢复上一位访客的关联。

两家模型使用相同状态结论和内部 `taskStatusQuery` 意图字段。模型识别为进度查询后，程序再次读取关联任务，覆盖模型的状态猜测，返回准确结论及 `selection:null`；普通选品仍返回原有 `reply/selection`。查询没有关联、记录损坏或状态未知时，回答暂时无法确认，并指引查看页面或联系工作人员。等待受理、已接单、完成、未接单、受理未确认、异常和人工解除各有独立结论；人工解除不代表取物完成。

页面任务卡和实时通知仍是共享展台状态；本批只隔离聊天查询，未改变通知归属或历史展示。模型仅获得当前体验关联的单任务结论，不获得全局任务列表、任务 ID 或体验凭据，也未新增完整聊天历史持久化。

## 保留的限制

无关联标识的机器人跨单迟到回调（P1）尚未修复，现有复现测试仍保留。聊天查询能核实记录归属，但不能消除机器人通知错写记录的风险。真正修复依赖[taskId 建议协议](task-id-proposal.md)得到确认，不能以本次会话关联或单任务锁代替。体验记录暂未增加自动过期或清理策略；其他浏览器引擎、真实设备和现场部署仍需后续验证。

## 后续：进度回答体验调整

本节记录 `5101166` 之后的小幅调整，不覆盖上述初版验证结果。用户已在实际浏览器确认任务进度可以查询，但完成回答重复通知、缺少对话感；这次调整后的真实模型表达尚未手动验证。

后端为当前核实状态提供准确结论和少量自然说法，两家模型沿用聊天上下文，根据用户原话选择其中一条。例如完成后直接询问可回答“已经取好了，请到交付处领取。”，追问可回答“现在已经取好了，到交付处领取就可以。”这是受约束的表达选择，不是开放式改写。模型返回后，后端重新读取当前关联任务，只有逐字匹配当前状态候选的进度回答才会保留，其他回答回退准确结论。人工解除、异常和无可靠关联均保持独立、安全的说法；任务关联、状态流转和机器人协议未修改。

自动化验证：API 和供应商配置检查共 62 项通过，类型检查和前端构建通过。新增受控 HTTP 测试覆盖两家模型的直接询问与追问、全部任务状态、错误完成话术、编造步骤及模型等待期间状态改变后的回退。实际浏览器回归 `booth-experience.cjs` 通过，覆盖刷新恢复、标签页隔离、新体验和异常处理；该脚本使用受控对端，验证已有功能，不证明新表达在真实模型上的选择效果。真实 AI、真实机器人调用均为零。

仍需实际观察两家模型是否恰当地选择直接回答和简短追问说法。模型将进度问题误判为普通问题时，仍不会触发进度回答审核，这是原有意图识别边界；本次未声称消除该限制。
