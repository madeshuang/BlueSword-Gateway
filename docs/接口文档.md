# AI 交互系统与机器人抓取系统接口文档

> 版本：v1.1
> 更新日期：2026-10-24
> 本次修订：建议使用 `items` 数组下发任务，`item` 使用物品清单中的 `id`。

本文中的“受理”指机器人接受任务，也称“接单”；“物品清单”指机器人团队提供的booth-catalog.example.json。

## 1. 对接范围

展会物品及其摆放位置预先固定。用户在我方前端选择物品后，我方将目标位置、物品和数量组成一条抓取指令；机器人侧接收并执行，完成后主动通知我方。物品与位置的对应关系需通过物品清单确定。

每次抓取指令表示一项完整取物任务，最多取两件：一种物品取一件或两件，或两种不同物品各取一件。

| 环节 | 发起方 | 接收方 | 预期反馈 |
|---|---|---|---|
| 下发抓取任务 | 我方 AI 交互系统 | 机器人抓取系统 | 机器人立即回复是否受理；受理不代表任务完成 |
| 任务完成通知 | 机器人抓取系统 | 我方 AI 交互系统 | 我方回复已收到通知 |
| 不可恢复故障上报 | 机器人抓取系统 | 我方 AI 交互系统 | 我方回复已收到故障消息 |

机器人执行中的导航、识别、抓取等步骤不逐项上报；我方不会定时向机器人查询状态。可自行恢复的故障由机器人侧处理，不上报。前端在受理后显示执行中，收到完成或不可恢复故障通知后更新展示。

## 2. 接口建议

任务指令和机器人主动通知均采用 **POST + JSON**。机器人侧提供任务接收地址，我方提供完成与故障通知的接收地址。

响应示例参考格式 `{code, data, success}`：`success` 表示本次接口调用是否成功，`data` 承载接单回复、通知接收确认或故障信息；示例中 `code` 为 `1`，不据此判断成败。

### 2.1 下发抓取任务

我方调用机器人侧提供的接口：

```http
POST /api/task/dispatch HTTP/1.1
Content-Type: application/json
```

本稿建议所有取物任务统一使用 `items` 数组，同一种物品合并为一项。

```json
{
  "items": [
    {
      "location": "货架1-2层",
      "item": "playing_card_box",
      "count": 1
    },
    {
      "location": "货架1-3层",
      "item": "pen_box",
      "count": 1
    }
  ]
}
```

| 字段 | 类型 | 含义与约束 |
|---|---|---|
| `items` | `array<object>` | 本次任务的物品列表，包含 1～2 项，各项的 `item` 不得重复 |
| `items[].location` | string | 该物品对应的取货位置，按现场物品清单填写；示例仅用于说明 |
| `items[].item` | string | 物品编码，取值为物品清单中的 `id`；`id` 与物品名称（`name`）的对应关系见物品清单 |
| `items[].count` | int | 该物品的抓取数量，为 1 或 2；所有项的 `count` 之和不得超过 2 |

取同一种物品两件时，`items` 只包含一项，`count` 为 2；取两种不同物品时，`items` 包含两项，每项的 `count` 均为 1。

机器人接单回复针对整个 `items` 列表，表示机器人是否接受本次完整取物任务。

机器人受理后的响应示例：

```json
{ "code": 1, "data": "received", "success": true }
```

不能受理时的响应示例：

```json
{ "code": 1, "data": "<未受理原因>", "success": false }
```

我方收到机器人明确接受任务的回复后进入“执行中”；任务是否完成，以机器人后续的完成通知为准。

### 2.2 任务完成通知

机器人完成本次请求中全部物品的取送，并在交付处放下后，向我方发送一次完成通知：

```http
POST /api/task/finished HTTP/1.1
Content-Type: application/json
```

请求体示例如下：

```json
{ "result": "success" }
```

我方收到后结束当前任务的“执行中”展示，并回复接收结果：

```json
{ "code": 1, "data": "OK", "success": true }
```

### 2.3 不可恢复故障上报

机器人遇到无法自行恢复的故障时，主动调用我方提供的接口：

```http
POST /api/task/error HTTP/1.1
Content-Type: application/json
```

```json
{ "message": "机械臂故障，无法自动恢复" }
```

`message` 为机器人侧给出的可读故障描述。仅凭该故障通知无法判断每件物品是否已取出或交付，实际物品情况需现场核对。我方收到后展示故障信息，并回复接收结果：

```json
{ "code": 1, "data": "OK", "success": true }
```

## 3. 补充说明

1. 任务与通知的对应关系： 当前报文不携带任务编号。上一任务的通知延迟到达或再次发送时，可能无法判断其对应哪次任务。后续如需增强任务与通知的关联，可另行约定增加 `taskId`。
2. 异常情况处理： 故障通知不表示机器人已经停止或恢复接单。长时间未收到完成或故障通知时，也不能据此认定任务完成。工作人员需核对机器人及物品情况后处理；必要时再补充超时处理和恢复接单的规则。
