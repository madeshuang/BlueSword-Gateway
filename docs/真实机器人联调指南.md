# 真实机器人联调指南

本文说明 Windows 下连接真实机器人的配置与联调步骤。首次使用先按 [README 第 1、2 节](../README.md#1-获取代码与安装依赖) 获取代码、安装依赖并配置 AI，再从本指南第 1 节开始操作。接口字段以[接口文档](接口文档.md)为准，常用词语见[项目术语说明](../GLOSSARY.md)。

## 1. 配置真实机器人

建议网关与机器人部署在同一局域网。机器人侧提供接收任务的完整地址，填入 `ROBOT_DISPATCH_URL`。同时，将网关电脑的局域网 IP、服务端口，以及完成和故障通知的接口地址提供给机器人侧，供机器人后续发送任务结果。

### 1.1 网络与机器人

在已完成 AI 配置的根目录 `.env` 中继续设置以下各项。下面是配置示例，需要逐项核实，机器人地址、物品清单和工作人员凭据尤其要按现场情况填写：

```dotenv
PORT=4100
BOOTH_HOST=0.0.0.0
BOOTH_ROBOT_MODE=http
ROBOT_DISPATCH_URL=http://<机器人IP>:<端口>/api/task/dispatch
ROBOT_TIMEOUT_MS=8000
BOOTH_TASK_REMINDER_MS=120000
BOOTH_CATALOG_PATH=config/booth-catalog.example.json
BOOTH_CATALOG_CONFIRMED=false
BOOTH_DB_PATH=.data/booth.sqlite
BOOTH_OPERATOR_TOKEN=<由现场负责人设置的工作人员凭据>
```

- `PORT`：网关服务端口，示例为 `4100`，可根据需要或实际情况自行修改。
- `BOOTH_HOST`：网关监听地址。`0.0.0.0` 表示允许通过本机各网络接口访问，便于同一局域网内的机器人填写访问地址时可使用本机电脑的实际 IP。
- `BOOTH_ROBOT_MODE`：机器人通信模式，连接真实机器人时设为 `http`。
- `ROBOT_DISPATCH_URL`：机器人接收取物任务的完整地址，须填写机器人团队提供的 IP、端口和接口路径。
- `ROBOT_TIMEOUT_MS`：等待机器人回复是否接单的最长时间，单位为毫秒。正式入口读取 `.env` 中的值，示例中的 `8000` 表示 8 秒，可按实际接单时间调整。从网关下发任务起计时；收到完整回复，或请求出错、超时后，这次等待结束。不要求在此期间完成取物，与下面的等待提醒时间独立。
- `BOOTH_TASK_REMINDER_MS`：任务等待提醒时间，单位为毫秒，`120000` 表示 2 分钟。从网关建立取物任务起计时，接单后继续累计，不重新开始。累计等待达到所设时长时，页面显示“等待时间较长，请联系工作人员核对”。

  网关确认机器人拒绝任务、收到完成或故障通知，或工作人员解除本单的新任务限制后，停止本单的等待计时和提醒。接单回复超时、无法确认是否接单时，仍继续计时。收到故障通知后会改为异常提示，仍需按第 4 节处理。

  等待提醒只提示联系工作人员，不会自动结束任务或解除新任务限制。

- `BOOTH_CATALOG_PATH` 指定网关读取的物品清单 JSON 文件，路径相对于项目根目录。示例文件中的初始库存为矿泉水 3、小面包 3、纪念品 2、蔬菜礼盒 1，仅用于演示，不代表现场实际库存。建议为现场单独准备一份配置：
  1. 将 `config/booth-catalog.example.json` 复制一份，命名为 `config/booth-catalog.site.json`。
  2. 编辑新文件，按现场实际情况填写各物品的 `name`（物品名称）、`location`（机器人取物位置）、`maxCount`（每单上限）和 `initialStock`（初始库存及补货目标数量）。
  3. 将根目录 `.env` 中的配置改为 `BOOTH_CATALOG_PATH=config/booth-catalog.site.json`，让网关读取这份现场物品清单。
- `BOOTH_CATALOG_CONFIRMED`：完成上述物品清单配置与核对后，设为 `true`；保持 `false` 时，网关不允许下发取物任务。
- `BOOTH_DB_PATH`：保存任务和库存的 SQLite 数据库文件路径，示例中的 `.data/booth.sqlite` 相对于项目根目录。
- `BOOTH_OPERATOR_TOKEN`：工作人员页面使用的凭据，由现场负责人设置，用于解除新任务限制和补货重置库存。

数据库上，真实联调默认使用 `.data/booth.sqlite`，人工入口固定使用 `.data/booth-manual.sqlite`，两者分别保存任务和库存。也可以为模拟联调设置单独路径，例如 `.data/booth-lan-test.sqlite`，避免练习记录影响真实联调的任务和库存。

### 1.2 启动与停止

完成配置后，双击根目录 **`start-gateway.cmd`**。脚本会检查类型、构建网页并启动网关。

如果习惯使用终端，也可以在项目根目录执行以下命令，两种方式任选其一：

```text
node scripts/start-local.cjs --gateway
```

如果浏览器没有自动打开，请手动访问下方地址；将 `<网关IP>` 替换为网关电脑在局域网中的实际 IP：

| 地址                               | 用途                             |
| -------------------------------- | ------------------------------ |
| `http://127.0.0.1:4100/`         | 在网关/本机电脑上打开主页面，进行 AI 对话、选品和取物。 |
| `http://<网关IP>:4100/api/health`  | 网关的后端健康检查，用于第 3.1 节机器人测的网络检查。  |
| `http://<网关IP>:4100/#operations` | 工作人员页面：处理异常和补货重置。              |
| `http://<网关IP>:4100/`            | 在其他设备上打开同一网关的主页面。              |

网页访问以及机器人向网关发送完成、故障通知共用 4100 端口。本机访问工作人员页面或健康检查时，可将 `<网关IP>` 换成 `127.0.0.1`。

保持进程和电脑在线。修改 `.env` 后重启生效，重新启动前先停止原服务，避免多个服务同时使用同一份任务和库存数据库。

先在网关主页面发送一条聊天消息，确认 AI 能够正常回复，暂不点击“确认取物”。如果显示“助手暂未配置，可直接选物品”，请核对 `.env` 中所选服务的密钥；提示“助手暂不可用”时，核对 [README 中的 AI 配置](../README.md#2-配置-ai)及网络。修改后重启，再验证回复。

## 2. 双方接口与报文

下表用于联调速查。请求方法、字段、响应格式和调用时机见[接口文档](接口文档.md)。

| 方向       | 地址                                                      | 内容                                             |
| -------- | ------------------------------------------------------- | ---------------------------------------------- |
| 网关 → 机器人 | `.env` 中 `ROBOT_DISPATCH_URL`，建议路径 `/api/task/dispatch` | `{"location":"货架1-2层","item":"矿泉水","count":1}` |
| 机器人 → 网关 | `http://<网关IP>:4100/api/task/finished`                  | `{"result":"success"}`                         |
| 机器人 → 网关 | `http://<网关IP>:4100/api/task/error`                     | `{"message":"机械臂故障，无法自动恢复"}`                   |

### 联调注意事项

- 网关默认等待机器人的接单回复 8 秒，可通过 `ROBOT_TIMEOUT_MS` 调整。如果超时或无法确认机器人是否接单，网关暂不接受新的取物任务，也不会自动重发本单。机器人可能已经收到任务，需要双方核对后再处理。
- 当前机器人通知不带任务编号，网关无法可靠判断通知属于哪一次取物。例如，上一单的通知在下一单开始后才到达，就可能被误认为当前任务的结果。应先约定通知重发规则：下一单开始后，不要重发上一单通知。
- 当前机器人接口未设置身份验证，工作人员凭据也不保护这些接口。联调时应限制为双方设备可访问的网络；如需公网连接，先由技术人员配置访问限制。

## 3. 真实联调顺序

先通过手动选择物品走通一次真实取物，再测试异常处理、补货和 AI 推荐。

### 3.1 确认双方网络连通

请机器人团队从机器人所在设备访问 `http://<网关IP>:4100/api/health`，检查响应中是否包含 `ok:true`。这表示网关后端可以访问，不代表 AI 可用或机器人接口已经连通。

同时，网关电脑上打开 PowerShell，执行以下命令，将 IP 和端口替换为 `ROBOT_DISPATCH_URL` 中的实际值。

```PowerShell
Test-NetConnection -ComputerName 192.168.1.20 -Port 8080
```

检查结果中的 `TcpTestSucceeded` 是否为 `True`。这表示机器人服务端口可以连接。实际接单能力仍需按下一节验证。如果机器人团队提供了健康检查接口，网关电脑也可以访问该接口进一步确认服务状态。

如果网络不通，先检查双方的 IP、端口、路由和网络访问限制，排除问题后再继续。不要反复下发真实取物任务来试探网络是否正常。

### 3.2 手选物品并检查机器人接单

在网关主页面选择 1 件有库存的物品，点击“确认取物”。请机器人团队检查收到的任务，确认物品、位置和数量与页面选择及现场配置一致。

机器人应先回复是否接受任务。接单后，检查网关页面是否继续等待取物结果；接单回复不代表取物完成。

### 3.3 完成实际取物并检查通知

等待机器人实际完成取物并放下物品，再由机器人发送完成通知。机器人团队检查是否收到网关确认已接收通知的回复，网关侧同时检查页面是否结束等待并显示完成回复。

完成后，页面右上角的任务状态应在约 10 秒后恢复为等待选择，已有聊天和任务记录应保留。

### 3.4 分别测试拒绝和故障

分别测试“机器人明确拒绝任务”和“机器人上报不可恢复故障”两种情况。

机器人明确拒绝后，检查网关是否将本次任务预留的数量退回可用库存。机器人上报不可恢复故障后，检查网关是否暂不接受新的取物任务，等待工作人员核对处理；现场人员核对机器人和物品情况后，再按第 4 节处理。

### 3.5 检查补货及重启后的数据

按第 4 节的说明，在核对实物后，分别测试单个物品和全部物品的补货重置，检查页面库存是否符合补满目标。

完成后，正常停止并重新启动网关，确认库存和任务记录仍然保留。

### 3.6 检查 AI 推荐后的取物流程

通过聊天让 AI 推荐物品，检查推荐的物品和数量是否正确；请求数量超过可取数量或每单上限时，检查是否有相应说明。

聊天推荐后，仍应由用户点击“确认取物”才下发任务。确认后，再按前面的步骤检查机器人的接单回复、实际取物和完成通知。

联调时请记录测试时间、双方软件版本（网关记录提交号）、实际使用的地址、任务物品及数量、请求与响应、页面结果，以及没有通过的项目，便于双方排查。

## 4. 现场异常处理

### 4.1 打开工作人员页面

在浏览器打开 `http://<网关IP>:4100/#operations`。访客页面没有固定入口，工作人员可以收藏这个地址。

操作时，在“工作人员凭据”栏输入现场负责人设置的凭据，即根目录 `.env` 中 `BOOTH_OPERATOR_TOKEN` 的值。这是工作人员操作口令，用于核实是否有权解除新任务限制或重置库存。真实联调不能使用本机人工练习的 `manual-local-only` 凭据。

### 4.2 发生故障或无法确认机器人是否接单

这两种情况下，网关会暂时阻止下发新任务，避免上一单尚未结束就发出下一单。请按以下顺序处理：

1. 现场确认机器人已经停止，并核对物品是否被取走、当前放在哪里。情况没有确认前，不要解除新任务限制。
2. 在工作人员页面输入凭据，勾选“已现场核对机器人停止及物品情况”。
3. 点击“解除新任务限制”，检查页面是否已解除对新任务的限制。

这个按钮只解除网关对新任务的限制，不会向机器人发送停止或取消指令，也不会恢复库存。如果物品需要补货，解除新任务限制后再按下一节操作。

工作人员页面不能取消执行中的任务，也不能仅凭等待时间较长就解除新任务限制。

### 4.3 补货后更新页面库存

只有库存不足，且没有未结束任务或告警时，直接进行补货操作即可，不需要点击“解除新任务限制”。如果还有未结束的任务或告警，先处理任务或异常，再重置库存。

补充一种物品时：

1. 在“补货重置”区域的“已补货物品”中选择该物品，查看当前剩余数量和“补满后”的目标数量。
2. 按目标数量补满实物，核对无误后，输入工作人员凭据，勾选“已核对并补满所选物品”。
3. 点击“重置所选物品库存”，检查页面数量是否已更新为补满目标。

如果所有物品都补满，在“已补货物品”中选择“全部物品”，逐项核对实物和目标数量，再输入凭据，勾选“已核对并补满全部物品”，点击“重置全部物品库存”。只补了一种物品时，应选择该物品，不要重置全部库存。

重置成功后，任务记录会保留，凭据和补货勾选会自动清空，按钮会再次变灰。下次操作时需要重新输入凭据并勾选确认，这是正常现象。具体数量规则见[库存说明](booth-inventory.md)。

真实联调的任务和库存保存在 `BOOTH_DB_PATH` 指定的数据库中。重启网关不会补满库存，不要通过删除或更换数据库来解除限制。
