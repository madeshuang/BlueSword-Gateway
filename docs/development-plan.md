# 下一阶段开发计划

目标是在 2026-10-12（周一）形成我方可运行、可进入后续联调的初版。先处理真实业务状态风险，尽早验证两个模型，再调整对话布局。周日不作为高强度开发预算；缺少真实账号、目录或接口确认时，必须明确列出缺口，不保证全部完成。

## 范围

本计划包括迟到结果保护、回调写入一致性、必要日志、GPT/DeepSeek 后端配置选择、等待提醒和对话式前端。机器人联调、正式部署、最终验收和通用网关平台不在本轮；自动故障切换是单独的增强项，范围确认前不实现。

## 已知风险与可执行工作

| 工作 | 优先级与证据 | 后续动作与完成条件 |
| --- | --- | --- |
| P1 跨任务迟到回调关联 | 高优先级；service.finished/error 将无关联标识的通知应用到当前 active，上一单迟到通知可能改变下一单状态。 | 向于总确认跨单重发行为及双方任务关联约定；先复现 A 完成、B 开始、A 通知迟到的场景。正式约定前记录限制与人工核对准入，不擅自给报文增加 taskId。约定后用正式回调 HTTP 边界验证跨单、重复及重启，不得把单任务锁当修复。 |
| P2 迟到 AI 建议覆盖改选 | 高优先级；BoothApp.chat 在响应返回后用发起时状态决定 choose，期间手动改选可能被覆盖。 | 在我方界面建立当前选择/对话版本的有效性判断，过期结果不改选。验证等待 AI 时改选、改数量、发单、开始新体验与延迟返回；建议不得自动发单。 |
| P3 回调审计与状态一致性 | 高优先级；回调 audit 与 update 当前是分开的 KV 写入。 | 在现有 SQLite 基础上原子写入回调审计和状态，提交成功后发布 SSE；验证写入失败、重复通知、重启恢复。无证据不加通用事务重试框架，不重试机器人副作用。 |
| P4 必要日志 | 与 P3 同阶段；已有数据库审计不足以解释调用与状态变化。 | 记录内部关联标识、状态变化、上游状态、供应商、耗时与错误类别；不记录密钥或完整敏感对话。核对异常和重启时能定位原因。 |
| P5 双供应商配置选择与真实调用 | 首版必需；已有 OpenAI Responses 代码和 5 项可控测试，无真实验证；DeepSeek 未实现。 | 使用同一消息输入与 reply/selection 业务输出，后端配置选择 GPT 或 DeepSeek，重启生效即可；前端不处理供应商协议。分别验证请求、响应、目录/数量校验、认证、限流、超时及无效输出。账号可用后尽早分别记录真实调用、语义结果和耗时。 |
| P6 长时间无通知与人工核对 | 首版重点；当前只显示等待，没有按任务时长触发提醒。 | 明确可配置提醒阈值与人工路径。等待过久只提醒并保留占用，不完成、不自动解锁；向于总确认正常时长、故障收尾及停止核对规则。验证提醒、断线/重连、异常凭据和恢复。 |
| P7 更简洁的对话布局 | 首版视觉方向；保留原 SVG、CSS 与排版基线，手机当前需滚动较长距离才到对话。 | 以 AI 对话为主，按需展示选品和数量确认卡片，确认后融入真实任务状态；保留模型不可用时的手动选择。开始新体验只清理访客对话/选择，不清除系统任务。验证桌面和手机视觉、键盘/触摸及稳定请求标识。 |
| P8 自动故障切换 | 范围待确认，不能代替 P5。 | 明确触发错误、备用次数、共同超时预算和验收范围后再排期；模型重试只生成建议，绝不触发机器人调用。认证/配置失败、安全拒绝或用户输入问题不得被当作常规瞬时错误自动绕过。 |
| P9 现场配置与交付收口 | 开发可独立推进，现场发单受配置限制。 | 获取真实物品/位置/数量、机器人完整 URL 与回调地址；仍未到位时保留示例和禁止发单。重跑正式接口、模型、异常、重启、浏览器流程；核对范围、维护启动说明和实际验证记录。 |
