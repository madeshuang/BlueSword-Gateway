# BlueSword-Gateway 联调指南

本文说明 Windows 下如何获取代码、配置 AI 并完成一次本机人工联调。AI 调用真实模型，机器人的接单回复和结果通知由人工模拟。连接真实设备见第 4 节。常用词语及容易混淆的含义见[项目术语说明](GLOSSARY.md)。

## 1. 获取代码与安装依赖

安装 Git、Node.js **24.13.0 或以上版本**，在准备存放项目的目录打开 PowerShell，执行：

```powershell
# 尚未安装指定版本的 pnpm 时执行
npm.cmd install --global pnpm@11.25.0

git clone https://github.com/madeshuang/BlueSword-Gateway.git
Set-Location BlueSword-Gateway
pnpm.cmd install --frozen-lockfile
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

后续命令均在项目根目录执行。

## 2. 配置 AI 并一键启动

根据你使用的模型服务，选择下面一种配置方式。修改时，将示例中带尖括号的内容替换为实际值，其他配置保留。

密钥只保存在本机，不提交 Git。用记事本保存配置时，请确认文件名仍为 `.env` 或 `.env.relay`，没有多出 `.txt` 后缀。

### 方式一：DeepSeek（.env）

打开第 1 节创建的 `.env`：

```powershell
notepad.exe .env
```

修改以下字段，模型名使用账号可用的名称：

```dotenv
BOOTH_AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=<你的DeepSeek密钥>
DEEPSEEK_MODEL=<你的DeepSeek模型名>
```

保存后双击 **`start-deepseek.cmd`**。

### 方式二：GPT 中转（.env.relay）

首次使用时复制模板，再打开配置文件；已有文件时保留原配置：

```powershell
if (-not (Test-Path .env.relay)) { Copy-Item .env.example .env.relay }
notepad.exe .env.relay
```

修改以下字段，使用中转服务提供的地址、模型名和密钥：

```dotenv
BOOTH_AI_PROVIDER=openai
OPENAI_BASE_URL=<中转服务的HTTPS API基址，包含所需版本路径>
OPENAI_MODEL=<中转服务支持的模型名>
OPENAI_API_KEY=<你的中转服务密钥>
```

中转服务及所选模型须支持 OpenAI Responses API 的结构化输出（JSON Schema，严格模式）。`OPENAI_BASE_URL` 填 API 基址，比如 `https://vip.auto-code.net/v1`，不要追加 `/responses`。

保存后双击 **`start-gpt-relay.cmd`**。

### 启动与停止

脚本会自动构建网页、启动服务，并打开网关主页面和人工机器人工具。联调时，在网关页面操作取物，再到人工工具中模拟机器人回复。需要处理异常或补货时，可以另行打开工作人员页面。

| 本机地址                                | 用途                            |
| ----------------------------------- | ----------------------------- |
| `http://127.0.0.1:4101/`            | 网关主页面：AI 对话、选择物品、确认取物和查看任务状态。 |
| `http://127.0.0.1:4201/`            | 人工机器人工具：接受或拒绝任务，发送完成或故障通知。    |
| `http://127.0.0.1:4101/#operations` | 工作人员页面：处理异常和补货重置。             |

页面打开后，先在网关的聊天框发送一条消息，确认 AI 能够正常回复，再进行下一节的取物测试。如果启动时提示端口占用，请先在原来的启动窗口停止旧服务，再重新启动。

联调期间保持启动窗口开启。结束时，在窗口中输入 `q` 后回车，或按 Ctrl+C，即可同时停止两个服务。修改配置或切换模型服务时，也需要先停止，再运行对应的启动脚本。

## 3. 走通一次人工联调

此时网关连接的是本机人工工具。需要在两个页面之间切换，分别完成用户取物和机器人回复的操作。

人工练习会等待 120 秒，供人查看任务并点击“接受任务”；真实联调默认等待机器人的接单回复 8 秒，可按需配置。这段时间只用于等待是否接单的回复，不要求在此期间完成取物。

1. 在网关主页面（4101）选择一件有库存的物品，点击“确认取物”。也可以先通过聊天让 AI 推荐物品，再确认取物；只有确认后，网关才会下发任务。
2. 切到人工机器人工具（4201），查看收到的任务，核对物品、位置和数量，并在 **120 秒内**点击“接受任务”。这一步表示机器人接受了任务，网关页面应继续等待取物结果。
3. 接单后先等几秒，确认网关不会自行完成，再在人工工具中点击“发送完成通知”。检查工具是否收到网关确认已接收通知的回复，以及网关页面是否显示取物完成。右上角的完成状态应保留约 10 秒后复位，聊天和任务记录仍保留。

等待期间，网关可能显示出发、抓取、返回等文字，这些是预设的模拟展示。只有在人工工具中发送完成通知后，这次模拟任务才会完成。

### 检查其他场景

以下检查使用手动选品即可，无需调用 AI。拒绝和故障须分别新建任务测试；补货和异常处理按下一节操作。

| 操作 | 应观察到的结果 |
| --- | --- |
| 发单后点击“拒绝任务” | 网关显示机器人未接单，本单预留的数量退回可用库存，无需发送完成通知。 |
| 接单后填写故障说明，点击“发送故障通知” | 工具收到网关确认已接收通知的回复；网关显示异常并阻止新任务，不显示取物完成。 |
| 现场核对后解除新任务限制，再分别测试单个物品和全部物品补货 | 解除限制不恢复库存；补货重置后，对应物品恢复到补满目标，另一页面同步更新，任务记录保留。有任务或告警时不能重置。 |
| 正常停止并重新启动网关 | 库存和任务记录保留，未结束的任务仍会阻止新任务，网关也不会自动重发原任务。 |

### 无法继续取物时

如果你在人工工具中发送了故障通知，或者没有及时点击“接受任务”，网关会暂不接受新的取物任务，等待工作人员核对处理。多次完成取物后，也可能遇到库存不足。这些情况需要到工作人员页面处理。

工作人员凭据是操作口令，用于核实是否有权解除新任务限制或重置库存。打开工作人员页面，在“工作人员凭据”栏输入本机练习凭据 **`manual-local-only`**，再根据页面状态操作：

- **故障或无法确认机器人是否接单**：先核对模拟任务和物品情况，确认可以结束本次练习任务后，勾选“已现场核对机器人停止及物品情况”，点击“解除新任务限制”，允许网关接收新任务。这个按钮不会向机器人发送停止或取消指令，也不会恢复库存，不能用于取消执行中的任务。
- **库存不足**：本机练习时可以模拟补货。在“补货重置”中选择需要补货的物品，或选择全部物品，核对页面显示的补满目标，勾选相应的补货确认，再重置库存。如果还有未结束的任务或告警，需要先处理，才能重置。

补货成功后，凭据和补货勾选会清空，下次操作须重新填写并确认。切换补货范围、库存变化或开始新任务后，也须重新核对并勾选。

本机库存和任务记录保存在 `.data/booth-manual.sqlite` 中。点击“开始新体验”只清空本页对话和选择，不取消后台任务，也不解除新任务限制；重启服务或开始新体验都会保留已有库存，因此需要补货时仍应使用上述操作，不要删除数据库来解除限制。

### 保存接口记录

人工工具下方可查看通信时间、方向、URL、方法、请求头、原始 JSON、HTTP 状态码和响应体；敏感请求头会隐藏。`headersScope` 说明头部记录范围：工具收到的请求以及网关对通知的回复，记录实际头部；工具发出的完成或故障通知以及接单回复，只记录工具显式设置的头部。

停止工具前，点击“下载本次接口记录 JSON”。工具只保留本次运行最近 200 条通信，重启后清空。保存时另记日期、操作者、电脑、Git 分支与提交号、双方地址，以及各场景的实际结果和未通过项。结果须按实际操作填写，不能用自动报告代填。接口记录不包含 AI 请求，也不能证明真实机器人动作。

## 4. 连接真实机器人

前面的步骤用于本机模拟。连接真实机器人时，请按[真实机器人联调指南](docs/真实机器人联调指南.md)完成配置、启动和现场验证。

切换前，请先停止本机模拟服务。真实机器人联调使用指南中的启动命令；本 README 中的一键脚本固定连接人工工具，不用于连接真实机器人。
